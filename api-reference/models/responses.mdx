## Overview

This page documents common response structures, pagination formats, and error handling patterns used across the Outlight API. Understanding these patterns will help you write more robust and predictable code.

## Standard Response Formats

### 1. Paginated List Response

Used for endpoints that return lists of items. While the structure is consistent, the specific keys for the data array and total counts vary by endpoint.

```typescript
// Generic structure - specific keys differ
interface PaginatedResponse<T> {
  // Data array - key varies
  channels?: T[];
  calls?: T[];
  data?: T[];
  
  // Pagination metadata
  currentPage: number;
  totalPages?: number;    // Used by Channel endpoints
  total_pages?: number;  // Used by Token endpoints
  
  // Total items - key varies
  totalChannels?: number;
  totalCalls?: number;
  total?: number;
}
```

#### Key Variations by Endpoint

| Endpoint | Data Array Key | Total Items Key | Total Pages Key |
|---|---|---|---|
| `/api/channels` | `channels` | `totalChannels` | `totalPages` |
| `/api/channels/{id}/calls`| `calls` | `totalCalls` | `totalPages` |
| `/api/tokens/recent` | `data` | `total` | `total_pages` |
| `/api/tokens/most-called`| `data` | `total` | `total_pages` |

### 2. Search Response

The structure of the search response **differs significantly** between channels and tokens.

#### Channel Search Response (`GET /api/channels/search`)

Returns a wrapper object containing the results array.

```typescript
interface ChannelSearchResponse {
  channels: Channel[]; // Array of Channel objects
  count: number;       // Number of results found
}
```

#### Token Search Response (`GET /api/tokens/search`)

Returns a **direct JSON array** of results, without any wrapper object.

```typescript
// The response body is the array itself
type TokenSearchResponse = TokenSearchResult[];
```

### 3. Single Item Response

For endpoints returning a single detailed resource, the response is the object itself, without any wrapper.

```typescript
// Example: GET /api/channels/{channelId}/info returns a ChannelInfo object directly.
type SingleItemResponse = ChannelInfo | TokenResponse;
```

## Error Responses

### Error Response Structure

All client (4xx) and server (5xx) errors return a standardized JSON error object.

```typescript
interface ErrorResponse {
  error: {
    code: string;           // Machine-readable error code
    message: string;        // Human-readable error message
    details?: any;          // Additional error details (optional)
    retry_after?: number;   // Seconds to wait before retry (for rate limiting)
  }
}
```

### Common Error Codes

| Code | HTTP Status | Description |
|---|---|---|
| `INVALID_PARAMETERS` | 400 | Request parameters are invalid or missing. |
| `RESOURCE_NOT_FOUND` | 404 | The requested resource (e.g., a specific channel) doesn't exist. |
| `RATE_LIMITED` | 429 | Too many requests; rate limit exceeded. |
| `INTERNAL_ERROR` | 500 | An unexpected error occurred on the server. |
| `SERVICE_UNAVAILABLE` | 503 | The service is temporarily unavailable, e.g., for maintenance. |

### Error Response Example (429 Rate Limited)
```json
{
  "error": {
    "code": "RATE_LIMITED",
    "message": "Rate limit exceeded. Please try again later.",
    "retry_after": 60
  }
}
```

## HTTP Status Codes

| Status | Category | Description |
|---|---|---|
| `200 OK` | **Success** | The request was successful. |
| `400 Bad Request` | **Client Error** | The request was malformed (e.g., invalid parameters). |
| `404 Not Found` | **Client Error** | The requested resource could not be found. |
| `429 Too Many Requests`| **Client Error** | You have hit the rate limit. |
| `500 Internal Server Error`| **Server Error** | Something went wrong on our end. |

## Response Headers

### Rate Limit Headers

Monitor these headers to manage your request rate and avoid 429 errors.

| Header | Description |
|---|---|
| `X-RateLimit-Limit` | The maximum number of requests allowed in the current time window. |
| `X-RateLimit-Remaining` | The number of requests remaining in the current window. |
| `X-RateLimit-Reset` | The Unix timestamp (in seconds) when the rate limit window resets. |

## Best Practices

### 1. Always Check Response Status

Before parsing the JSON, verify that the HTTP response status is successful (e.g., `response.ok` in JavaScript).

```javascript
const response = await fetch(url);

if (!response.ok) {
  const errorPayload = await response.json();
  console.error("API Error:", errorPayload.error.message);
  throw new Error(errorPayload.error.message);
}

const data = await response.json();
```

### 2. Handle Pagination Dynamically

Don't assume a fixed number of pages. Use the `totalPages` or `total_pages` field from the response to determine if more data is available.

```python
def fetch_all_calls(channel_id: str):
    """Fetches all pages of a channel's calls."""
    all_calls = []
    page = 1
    
    while True:
        response = requests.get(
            f"https://prod.api.sauron.outlight.fun/api/channels/{channel_id}/calls",
            params={'page': page, 'limit': 500} # Use max limit
        )
        response.raise_for_status()
        data = response.json()
        
        all_calls.extend(data.get('calls', []))
        
        if page >= data['totalPages']:
            break
            
        page += 1
    
    return all_calls
```

### 3. Implement Retry Logic for Rate Limits

When you receive a `429` status code, wait for the duration specified in the `retry_after` field of the error response or the `Retry-After` header before trying again.

```typescript
async function fetchWithRetry(url: string, maxRetries: number = 3): Promise<any> {
  for (let i = 0; i < maxRetries; i++) {
    const response = await fetch(url);
    
    if (response.status === 429) {
      const error = await response.json();
      const retryAfter = error.error.retry_after || 60;
      console.log(`Rate limited. Retrying in ${retryAfter} seconds...`);
      await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
      continue; // Retry the loop
    }
    
    if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
    }

    return response.json();
  }
  
  throw new Error('Max retries exceeded');
}
```
