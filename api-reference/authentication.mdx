## Overview

The Outlight API is currently public and does not require an authentication token or API key. All endpoints documented in this reference are accessible to anyone.

However, to ensure fair usage and system stability, public endpoints are subject to **rate limiting**. This page explains how to monitor your usage and handle rate limits gracefully.

## Request Headers

While authentication is not required, we recommend including standard headers in your requests for better tracking and compatibility.

```http
GET /api/channels/search?q=crypto&limit=10
Host: prod.api.sauron.outlight.fun
Content-Type: application/json
Accept: application/json
User-Agent: YourAppName/1.0
```

## Rate Limiting

<Warning>
  Exceeding the request limit will result in a `429 Too Many Requests` error. All public endpoints are rate-limited.
</Warning>

### Rate Limit Headers

You can monitor your current rate limit status by inspecting the following headers in every API response:

| Header | Description |
|---|---|
| `X-RateLimit-Limit` | The maximum number of requests you can make in the current time window. |
| `X-RateLimit-Remaining` | The number of requests you have left in the current window. |
| `X-RateLimit-Reset` | The Unix timestamp indicating when the current window resets. |

### Rate Limit Response

If you exceed the limit, the API will respond with a `429` status code. The response body will follow the standard [Error Response structure](/api-reference/models/response-models#error-response-structure) with the code `RATE_LIMITED`.

## Best Practices

### 1. Implement Retry Logic

The most important practice is to handle rate limits gracefully by implementing a retry mechanism with backoff.

```python
import time
import requests

def api_request_with_retry(url, params, max_retries=3):
    for attempt in range(max_retries):
        response = requests.get(url, params=params)
        
        if response.status_code == 429:
            error = response.json().get('error', {})
            retry_after = error.get('retry_after', 60)
            print(f"Rate limited. Retrying in {retry_after} seconds...")
            time.sleep(retry_after)
            continue
        
        response.raise_for_status() # Raise an exception for other errors
        return response.json()
    
    raise Exception("Max retries exceeded")
```

### 2. Cache Responses

Cache responses for frequently accessed data to reduce the number of API calls you make.

```javascript
const cache = new Map();
const CACHE_TTL = 5 * 60 * 1000; // 5 minutes

async function getCachedData(key, fetchFn) {
  const cached = cache.get(key);
  
  if (cached && (Date.now() - cached.timestamp < CACHE_TTL)) {
    return cached.data;
  }
  
  const data = await fetchFn();
  cache.set(key, { data, timestamp: Date.now() });
  return data;
}
```

### 3. Use Pagination Efficiently

When fetching lists of data, request only the number of items you need per page instead of always requesting the maximum.

```python
# Good: Request a specific page size
params = {"page": 1, "limit": 20}

# Avoid: Requesting the maximum limit unnecessarily
# params = {"page": 1, "limit": 200}
```
